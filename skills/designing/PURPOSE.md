# Rule purposes

Maintenance record; not runtime guidance.

| Rule | Motivating pattern |
| --- | --- |
| Choose actual capabilities | Provider-specific tool names and mandatory image generators block otherwise capable hosts. |
| Use vectors for suitable marks | Simple editable geometry can be delivered without raster generation; wrapping a bitmap in SVG does not make it vector. |
| Native transparency then verification | Opaque white or checkerboard previews and fully opaque alpha channels are not transparent deliverables. |
| Respect logo type and accepted identity | Symbol-only requests do not need forced brand lettering; narrow edits should preserve the existing system. |
| Scope evidence-based checks | Mockups do not establish originality, font rights, print accuracy, or whole-product accessibility. |
| Inventory real deliverables | Concept descriptions, generated assets, unrendered source, and missing exports have different usability. |
