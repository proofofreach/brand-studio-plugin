# Brand Building

Build a usable, coherent system: one strategic idea expressed through visuals, language, and relevant applications. Match the kit to the user's scope. Preserve supplied names, assets, and approved decisions unless the task changes them.

## Establish the foundation

Use the brief and available brand/product documents to identify audience, category, problem served, offer, differentiation, personality, and important touchpoints. Distinguish supplied facts from proposed positioning and assumptions. Ask only for information that materially blocks the assignment; a workable brief does not require a questionnaire.

Naming is optional and belongs here only when requested or unresolved. If useful, choose a provisional name and continue the kit. Do not claim domain availability, cultural suitability, competitor research, font rights, or trademark clearance without evidence. Search is optional and depends on available host capabilities; lack of browsing does not prevent a provisional design.

## Connect visual and verbal choices

1. **Positioning:** Write a concise audience/problem/offer/difference statement. Anchor values in behaviors rather than unsupported claims. State proposed strategy as a proposal, not research findings.
2. **Visual system:** Establish a logo direction or supplied mark, a palette with functional roles, typography hierarchy, and any needed imagery or graphic devices. Include practical usage guidance suited to the actual applications. An icon-only mark need not acquire a wordmark.
3. **Voice and messaging:** Define a few usable voice traits, tone changes by context, message hierarchy, and before/after or sample copy. Connect benefits to supported product facts; do not invent testimonials, metrics, guarantees, scarcity, sustainability claims, or offer terms.
4. **Applications:** Demonstrate the system in a small set of requested or representative touchpoints. Reuse the same name, palette, type roles, tone, and factual claims throughout. Do not add a campaign, website, or social publishing task merely because it could use the kit.
5. **Guidelines:** Consolidate the decisions and their practical use, then check coherence. A simple kit may be one page; a full identity may need sections and an asset inventory. Do not force phase approvals when the user has authorized the work.

## Use skills and tools that exist

If installed and accessible, use the sibling skills for deeper work:

- [copywriting](../copywriting/SKILL.md): copy, offer presentation, audience awareness, and editing.
- [designing](../designing/SKILL.md): logo production, color, typography, and visual verification.

Load them only for the parts needed. If installed separately or unavailable at those paths, use the host's skill discovery if provided; otherwise follow the core procedure here and describe any resulting limits. Missing sibling skills do not block a useful kit. This coordination does not require subagents, workflows, or invented tool calls.

Use the current host's documented capabilities. A tool offered by one provider is not assumed to exist in another. Prefer editable vector construction for suitable simple marks; use available raster generation for illustrative assets. A raster in an SVG wrapper is not a vector logo. If visual production is unavailable, deliver clearly labeled concepts and specifications without pretending to have generated assets. Use file writing and exports only when available; otherwise return the content directly.

For transparent images, request documented native transparency first. Verify actual alpha, transparent pixels, and edges when inspection is possible; label unchecked output unverified. Do not default to chroma-key backgrounds or call opaque previews transparent. If no reliable export path exists, mark that deliverable incomplete and supply the usable source or handoff.

## Deliver and reconcile

A kit should contain only the relevant parts of:

- Brand foundation and positioning.
- Visual identity rules, including actual colors, type roles, logo use, and dependencies.
- Voice and messaging rules with concrete examples.
- Applications that demonstrate consistent use.
- An inventory of actual assets and their verification status, plus outstanding decisions or exports.

Check consistency across the document and assets: exact brand spelling, approved variants, color values, font names, tone, and offer terms. Distinguish supplied files, newly created files, proposals, and exports that could not be made. Do not invent file links, claim visual inspection without access, promise conversion gains, or treat a research hypothesis as proof.

Scope verification honestly: color-pair calculations do not certify a whole product, print colors require a specified profile/proof, and font/trademark claims require supporting checks. Where a value is unknown, mark it as proposed or unresolved rather than silently changing an accepted identity. Do not publish the kit or register names unless the user has authorized those actions.
